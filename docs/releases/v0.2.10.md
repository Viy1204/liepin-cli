# v0.2.10

修复推荐结果到简历详情的 ID 衔接、简历字段丢失，以及触达命令的发送误判。

## 简历与候选人标识

- `recommend` 从推荐 URL 的 `resIdEncode` 提取 `resume_id`，可直接传给 `resume`；保留旧 `talentId` 供兼容，但它不能代替简历 ID。表格完整显示新增 ID。
- `resume` 工作职位优先显示 `title`，避免把 `N002026` 等分类编码当作职位名称。
- 工作和教育经历保留接口返回的起止年月及原有时长，不推算缺失日期。
- 候选人 IM 标识优先读取 `imInfoVo.usercImId`，兼容旧 `resumeDetailVo.imId`。

## 触达结果

- `greet` 在平台动作前拒绝 `user_id + --message`，避免先发默认招呼再报参数错误。沟通权限接口失败时停止开聊。
- 已有会话且没有自定义消息时，明确返回“本次未发送新消息”。
- `greet` 新增 `confirmed`。已有会话的自定义文本只有在聊天记录中出现新增、己方发送且全文匹配的消息时才确认；历史同文、页面正文和草稿不算。
- 新开聊同时补发自定义文本时，无法排除预设招呼延迟出现的干扰，保守返回 `confirmed: false`。默认开聊只有接口成功也不代表发送已确认。
- `request-phone` / `request-resume` 只确认本次新增、己方发送且类型匹配的请求卡片；无关来信和按钮变灰不再作为确认依据。
- 发送前查询基线失败时停止；发送后无法确认时提示人工核对，不自动重发。页面清空、验证页或连接失效仍沿用退出码 `3` 的停止语义。

`success: true` 保持操作完成的含义，不能替代发送确认。`confirmed` 不表示候选人已经阅读或同意请求。
