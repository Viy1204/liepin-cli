# v0.2.9

修复招聘者页面连接与错误传播，补充聊天消息中的简历标识。默认有头浏览器、固定调试端口、Windows WMI 启动和跨命令常驻保持现有行为。

## 页面会话与错误处理

- 生产页面操作使用有限的 `RecruitPageSession`，覆盖导航、求值、元素等待和点击，按需执行页面协议操作。
- 主页面清空、执行中导航或连接断开时停止，抛出 `PageUnavailableError` 并沿用退出码 `3`。保留浏览器，涉及发送的结果需要人工核对，不自动重试或重发。
- 索要手机号/简历等待按钮时，认证或页面失效错误原样传播，不再误报按钮缺失并建议重新打招呼。
- 登录等待检查页面历史故障和连接状态。短暂清页后恢复、URL 未变但连接断开，不再被当作普通登录超时。
- 页面 session 独立分离时立即结束等待，保留正确的异常类型并释放监听。

## 聊天简历标识

- 保留 `0.2.8` 的 `source/ext_type/biz_type/biz_key` 字段。
- 简历卡片中的历史 ID 输出为 `card_resume_id`，不将其当作当前简历 ID。
- 显式使用 `chatmsg "<im_id>" --resolve-resume --json` 时，从目标简历卡片增加一次只读请求解析当前 `resume_id`。默认关闭；没有合适卡片或标识不一致时直接报错，不回退到历史 ID。

## 验证

- 构建通过，完整离线测试 148 项、实验控制器测试 5 项均通过，无失败、无跳过。
- 临时 profile、独立端口和本地 HTML 的 adapter / production 验收覆盖导航、参数、点击、异常和断连停止。
- 打包后从真实 CLI 入口使用合成数据验证 JSON、表格完整 ID、解析开关与页面失效退出码；实验和测试文件不进入 npm 包。
- 独立复核通过。CI 覆盖 Node.js 20、22、24，实验控制器仅在 Node 24 执行。

本次整理未调用真实猎聘账号或发送候选人消息。历史本机在线验证的范围见[页面会话记录](../../experiments/issue23-ui/2026-10-27-page-session.md)。尚未验证 macOS / Chrome 155、跨版本长期运行或其他并行客户端，也未解决裸 `flag:0` 响应的具体成因；[Viy1204/liepin-cli#23](https://github.com/Viy1204/liepin-cli/issues/23) 继续保持开放。
